# 9.2 Coupling Health

## What Question Does This Answer?

> **"How densely interconnected are the files and symbols of this repository in terms of total structural relationships?"**

More specifically: *"On average, how many edges — both incoming and outgoing, of any relationship kind — does each relevant node in the graph participate in?"*

Coupling Health captures the **overall structural connectivity** of the graph. It is the second most heavily weighted metric (23%) because high coupling is a broad architectural concern: when many components are structurally linked to many others, changes propagate more widely and the system becomes harder to reason about, test, and refactor in isolation.

Coupling is distinct from fan-out and fan-in:

- **Fan-out** measures only outgoing edges — what does a node point to?
- **Fan-in** measures only incoming edges — what points at a node?
- **Coupling** measures both together — how broadly is a node embedded in the graph's structure?

| Field | Type | Description |
|-------|------|-------------|
| `score` | `number` | Normalized health score, 0–100. Higher is healthier. |
| `averageStructuralDegree` | `number` | Average total degree (incoming + outgoing edges) per relevant node. |
| `normalizedRisk` | `number` | `0.5 × averageStructuralDegree`. The intermediate risk value fed into the health formula. |

---

## What "Structural Degree" Means

The **structural degree** of a node is the total count of edges that touch it:

$$
\text{StructuralDegree}(n) = |\text{IncomingEdges}(n)| + |\text{OutgoingEdges}(n)|
$$

This counts all relationship kinds — imports, calls, extends, implements, instantiates — without distinction. The degree represents the node's total participation in the graph's edge structure.

### Intuition

A node with degree 0 is structurally isolated — nothing depends on it and it depends on nothing.

A node with degree 1 either points to one thing or one thing points to it.

A node with degree 10 participates in 10 total relationships, distributed in some combination of incoming and outgoing.

The **average** structural degree across all relevant nodes gives a single number that summarizes how connected the entire graph is.

---

## Relevant Node Set

The coupling calculation considers only:

- **File nodes** (`kind === "file"`)
- **Symbol nodes** (`kind === "symbol"`)

Dependency nodes and module nodes are excluded. This focuses the metric on the repository's own internal structure rather than on the graph's bookkeeping nodes.

```ts
const nodeIds = [
    ...(graph.nodesByKind.get("file")   ?? new Set<string>()),
    ...(graph.nodesByKind.get("symbol") ?? new Set<string>()),
];
```

## Raw Measurement

```ts
let totalDegree = 0;

for (const nodeId of nodeIds) {
    const fanIn  = graph.incomingEdges.get(nodeId)?.size ?? 0;
    const fanOut = graph.outgoingEdges.get(nodeId)?.size ?? 0;
    totalDegree += fanIn + fanOut;
}

const averageStructuralDegree = totalDegree / nodeIds.length;
```

$$
\text{AverageStructuralDegree} = \frac{\sum_{n \in \text{RelevantNodes}} (\text{InDegree}(n) + \text{OutDegree}(n))}{|\text{RelevantNodes}|}
$$

### Empty graph

If `nodeIds.length === 0`, the function returns early with:

```ts
{ score: 100, averageStructuralDegree: 0, normalizedRisk: 0 }
```

An empty graph has no structural risk.

---

## Normalization

### Calibration factor

$$
F_{\text{coupling}} = 0.5
$$

### Normalized risk

$$
\text{NormalizedRisk} = F_{\text{coupling}} \times \text{AverageStructuralDegree}
$$

$$
\text{NormalizedRisk} = 0.5 \times \text{AverageStructuralDegree}
$$

### Health score

$$
\text{CouplingHealth} = \frac{100}{1 + \text{NormalizedRisk}}
$$

$$
\text{CouplingHealth} = \frac{100}{1 + 0.5 \times \text{AverageStructuralDegree}}
$$

This is **reciprocal normalization**. The score starts at 100 when degree is 0 and decreases continuously as degree increases, but it never reaches 0 (it approaches 0 asymptotically).

### Key properties of this formula

At degree = 0:
$$\text{CouplingHealth} = \frac{100}{1 + 0} = 100$$

At degree = 2:
$$\text{CouplingHealth} = \frac{100}{1 + 1} = 50$$

At degree = 4:
$$\text{CouplingHealth} = \frac{100}{1 + 2} = 33.3$$

At degree = 10:
$$\text{CouplingHealth} = \frac{100}{1 + 5} = 16.7$$

The denominator `1 + 0.5x` ensures the score is always positive and always decreasing. There is no threshold at which coupling "becomes bad." It is bad proportionally.

## Full Implementation

```ts
const COUPLING_FACTOR = 0.5;

export function calculateCouplingHealth(graph: Graph): CouplingHealthResult {
    const nodeIds = [
        ...(graph.nodesByKind.get("file")   ?? new Set<string>()),
        ...(graph.nodesByKind.get("symbol") ?? new Set<string>()),
    ];

    if (nodeIds.length === 0) {
        return { score: 100, averageStructuralDegree: 0, normalizedRisk: 0 };
    }

    let totalDegree = 0;

    for (const nodeId of nodeIds) {
        const fanIn  = graph.incomingEdges.get(nodeId)?.size ?? 0;
        const fanOut = graph.outgoingEdges.get(nodeId)?.size ?? 0;
        totalDegree += fanIn + fanOut;
    }

    const averageStructuralDegree = totalDegree / nodeIds.length;
    const normalizedRisk          = COUPLING_FACTOR * averageStructuralDegree;
    const score                   = 100 / (1 + normalizedRisk);

    return { score, averageStructuralDegree, normalizedRisk };
}
```

## Worked Examples

### Example A — Sparsely connected graph

```text
Total relevant nodes: 1000 (files + symbols)
Total edges touching relevant nodes: 200

AverageStructuralDegree = 200 / 1000 = 0.2
NormalizedRisk          = 0.5 × 0.2  = 0.10
CouplingHealth          = 100 / 1.10 ≈ 90.9
```

Very low average degree — most nodes are either isolated or have only one or two edges. Coupling is excellent.

### Example B — Moderate connectivity (realistic)

```text
Total relevant nodes: 28000
Total edge-touches: 5560

AverageStructuralDegree = 5560 / 28000 ≈ 0.1987
NormalizedRisk          = 0.5 × 0.1987 ≈ 0.0994
CouplingHealth          = 100 / 1.0994 ≈ 90.96
```

A large repository with a relatively sparse graph. The average node participates in fewer than one edge (many nodes are leaves). This results in a near-excellent coupling score.

### Example C — Dense internal graph

```text
Total relevant nodes: 500
Total edge-touches: 3000

AverageStructuralDegree = 3000 / 500 = 6.0
NormalizedRisk          = 0.5 × 6.0  = 3.0
CouplingHealth          = 100 / 4.0  = 25.0
```

An average of 6 edges per node is quite dense. The score of 25 falls in the "Significant structural concerns" range. This kind of coupling typically indicates a monolithic structure where most components are directly aware of many others.

## Why Average Degree and Not RMS?

Fan-out and Fan-in metrics use Root Mean Square (RMS) to detect concentration of connectivity in a small number of hub nodes.

Coupling uses the **simple average** because:

- The purpose of coupling is to measure the **general structural density** of the entire graph, not to detect hotspots.
- A few very highly connected nodes (which RMS would amplify) are already captured by the Fan-in and Fan-out metrics.
- Coupling's role is complementary — it answers "on average, how connected is this graph?" while fan metrics answer "are there dangerous concentrations of connectivity?"

Using RMS for coupling would create double-counting of the same information that fan-in and fan-out already penalize.

---

## Relationship to Fan-in and Fan-out

The three metrics relate mathematically:

$$
\text{StructuralDegree}(n) = \text{FanIn}(n) + \text{FanOut}(n)
$$

$$
\text{AverageStructuralDegree} = \text{AverageFanIn} + \text{AverageFanOut}
$$

The coupling average is the sum of the fan-in average and the fan-out average. However, the health scores diverge because:

- Coupling uses a simple average.
- Fan-in and fan-out use RMS, which emphasizes outliers.

A repository with uniformly moderate fan-in and fan-out will score similarly on all three metrics. A repository with a few hotspot nodes will score worse on fan-in and fan-out than on coupling, because the RMS amplifies those hotspots while the simple average smooths them.

## Interpreting the Score in Context

| CouplingHealth | Structural Signal |
|----------------|-------------------|
| 85 – 100 | Very low average connectivity. The graph is sparse and loosely connected. |
| 70 – 85 | Low to moderate connectivity. A reasonable degree of internal coupling. |
| 50 – 70 | Moderate to high coupling. The average node participates in 1–3 total relationships. |
| 30 – 50 | High coupling. Consider whether many relationships are necessary or can be decoupled. |
| 0 – 30  | Very high coupling. Nearly every component is heavily embedded in the graph structure. |

---

## Calibration Parameter

The factor `0.5` controls the coupling score's sensitivity. Reducing it makes the score more lenient (higher scores for the same degree). Increasing it makes it more strict (lower scores for the same degree).

The current value of `0.5` means:

- A degree of 2 produces exactly 50 coupling health (`100 / (1 + 0.5×2) = 100/2 = 50`).
- Equivalently, a "50% health" degree threshold is at average degree = 2.
