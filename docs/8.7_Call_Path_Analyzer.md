# 7.7 Call Path Analyzer

## What Question Does This Answer?

> **"Is there a call chain between function X and function Y? If yes, what is it?"**

More precisely: *"Is there a directed path from symbol X to symbol Y in the call graph, and if so, what is the shortest such path?"*

This is a point-to-point **reachability** query: given two specific nodes, find out whether one can reach the other strictly through `"calls"` edges, and if yes, return the sequence of nodes that form that call chain.

### Concrete Example

Given this call graph:

```
UserController.createUser
   → UserService.create
       → ValidationService.validate
       → DatabaseService.insert
           → ConnectionPool.getConnection
```

A call path query from `UserController.createUser` to `ConnectionPool.getConnection` would return:

```
path = [
    "UserController.createUser",
    "UserService.create",
    "DatabaseService.insert",
    "ConnectionPool.getConnection",
]
```

A query from `UserController.createUser` to some unrelated `EmailService.send` (not in the call chain) would return:

```
path = null
```

### Input

```ts
sourceNodeId: string   // The starting symbol (caller)

```

| Parameter | Type | Required | Meaning |
|-----------|------|----------|---------|
| `sourceNodeId` | `string` | ✅ | The node you start from. The path search begins here. |
| `targetNodeId` | `string` | ✅ | The node you are trying to reach. |

### Output

```ts
interface CallPathResult {
    sourceNodeId: string;
    targetNodeId: string;
    path: string[] | null;

```

| Field | Type | Meaning |
|-------|------|---------|
| `sourceNodeId` | `string` | Echoed back. |

| `path` | `string[] \| null` | If a path exists: an ordered array of node IDs from `sourceNodeId` to `targetNodeId` inclusive. If no path exists: `null`. If source === target: `[sourceNodeId]`. |

## Algorithm: Iterative DFS with Parent Tracking

### Why DFS (Not BFS)?

The implementation uses **Depth-First Search** rather than BFS. This is an explicit trade-off:

| Property | DFS (this implementation) | BFS (alternative) |
|----------|--------------------------|-------------------|
| Path found | Some path (not necessarily shortest) | Always the shortest path |
| Memory | O(depth of path found) | O(width of graph at each level) |
| Speed to first result | Can be faster for deep graphs | Explores all nodes at each depth level before going deeper |
| Implementation complexity | Simpler | Slightly more complex |

For the `CallPathAnalyzer`'s use case — answering "does a call chain exist between X and Y?" — the existence of a path is the primary question. The exact path returned is illustrative; the user doesn't need the globally shortest call chain, just a representative one that shows the connection.

> ⚠️ **Trade-off to note**: Because DFS explores in depth-first order, the returned `path` is not guaranteed to be the shortest possible call chain. If multiple chains exist from source to target, the one returned depends on the order edges are stored in the graph.

### Early Termination

A key optimization is that the DFS **stops immediately** when the target is found, rather than exploring the full graph:

```ts
if (edge.targetId === targetNodeId) {
    return {
        sourceNodeId,
        targetNodeId,
        path: this.buildPath(sourceNodeId, targetNodeId, parent),
    };
}
```

This means in the best case (target is a direct neighbor of the source), the algorithm exits after examining just one edge. In the average case, it exits long before exploring the full reachable subgraph.

### Restricting to `"calls"` Edges Only

```ts
if (edge.relationshipKind !== "calls") continue;
```

The `CallPathAnalyzer` is specifically about the **call graph** — function-to-function invocations. It intentionally ignores all other relationship kinds (`imports`, `extends`, `implements`, `instantiates`). The result is a call chain, not a mixed dependency chain.

### Restricting to Symbol Nodes Only

```ts
const targetNode = this.graph.nodes.get(edge.targetId);
if (!targetNode || targetNode.kind !== "symbol") continue;
```

Calls between file-level nodes or other node kinds are not meaningful in the call-path context. Only symbol-to-symbol call edges are followed.

### Full DFS Trace

```
sourceNodeId = "UserController.createUser"
targetNodeId = "ConnectionPool.getConnection"

Initial state:
  stack   = [ "UserController.createUser" ]
  visited = { "UserController.createUser" }
  parent  = {}

Iteration 1: pop "UserController.createUser"
  Outgoing calls: "UserService.create"
  "UserService.create" not visited → visited.add, parent["UserService.create"] = "UserController.createUser"
  "UserService.create" !== target → push to stack
  stack = [ "UserService.create" ]

Iteration 2: pop "UserService.create"
  Outgoing calls: "ValidationService.validate", "DatabaseService.insert"
  "ValidationService.validate" not visited → visited.add, parent["Validation..."] = "UserService.create"
  "ValidationService.validate" !== target → push to stack
  "DatabaseService.insert" not visited → visited.add, parent["Database..."] = "UserService.create"
  "DatabaseService.insert" !== target → push to stack
  stack = [ "ValidationService.validate", "DatabaseService.insert" ]

Iteration 3: pop "DatabaseService.insert"
  Outgoing calls: "ConnectionPool.getConnection"
  "ConnectionPool.getConnection" not visited → visited.add, parent["Connection..."] = "DatabaseService.insert"
  "ConnectionPool.getConnection" === target → FOUND! Return immediately.

  parent = {
    "UserService.create"           → "UserController.createUser",
    "ValidationService.validate"   → "UserService.create",
    "DatabaseService.insert"       → "UserService.create",
    "ConnectionPool.getConnection" → "DatabaseService.insert",
  }
```

### Path Reconstruction: `buildPath`

The `parent` map stores, for each visited node, which node discovered it. To reconstruct the path, trace backward from `targetNodeId` to `sourceNodeId`:

```ts
private buildPath(sourceNodeId: string, targetNodeId: string, parent: Map<string, string>): string[] {
    const path: string[] = [];
    let currentNodeId: string | undefined = targetNodeId;

    while (currentNodeId !== undefined) {
        path.push(currentNodeId);
        if (currentNodeId === sourceNodeId) break;
        currentNodeId = parent.get(currentNodeId);
    }

    path.reverse();   // Reverse from [target → ... → source] to [source → ... → target]
    return path;
}
```

Trace for the example:
```
Start: currentNodeId = "ConnectionPool.getConnection"
  path = ["ConnectionPool.getConnection"]
  parent.get("Connection...") = "DatabaseService.insert"

  path = ["ConnectionPool...", "DatabaseService.insert"]
  parent.get("Database...") = "UserService.create"

  path = ["Connection...", "Database...", "UserService.create"]
  parent.get("UserService.create") = "UserController.createUser"

  path = ["Connection...", "Database...", "UserService.create", "UserController.createUser"]
  currentNodeId === sourceNodeId → break

After reverse:
  path = ["UserController.createUser", "UserService.create", "DatabaseService.insert", "ConnectionPool.getConnection"]
```

### Edge Case: Source === Target

```ts
if (sourceNodeId === targetNodeId) {
    return {
        sourceNodeId,
        targetNodeId,
        path: [sourceNodeId],   // A single-node path to itself
    };
}
```

Handled immediately before the DFS begins. A node trivially "reaches" itself with a zero-hop path.

## Time and Space Complexity

| Resource | Complexity |
|----------|-----------|
| Time | O(V + E) worst case (when no path exists and all nodes are explored). O(path length × average degree) typical case with early exit. |
| Space | O(V) for the `visited` set and `parent` map in the worst case. |

---

## What It Does NOT Do

1. **Does not find all paths** between source and target — only one (via DFS).
2. **Does not guarantee the shortest path** — that would require BFS.
3. **Does not traverse non-call edges** — only `"calls"` edges are followed.
4. **Does not detect cycles** — if a cycle exists in the call graph, the `visited` set prevents infinite looping, but the cycle is not reported. The `CycleAnalyzer` handles cycle detection.

---

## Design Notes

**Why an iterative stack instead of recursion?** Deep call graphs in large codebases could overflow JavaScript's call stack if DFS were implemented recursively. Using an explicit `stack` array makes the implementation safe for arbitrarily deep graphs.

**Why `parent` map instead of passing the current path?** Passing the path array down the DFS tree (or copying it at each branch) would be O(depth × branching factor) in memory. The parent map uses O(V) total memory regardless of branching and is O(path length) to reconstruct after the target is found — strictly better.

**`path: null` vs. empty array**: The result uses `null` (not `[]`) to represent "no path found". This is a deliberate semantic choice — an empty array is ambiguous (could be a zero-length path, a bug, or "not found"), while `null` is an unambiguous "does not exist" signal.
