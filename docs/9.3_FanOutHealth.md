# 9.3 Fan-out Health

## What Question Does This Answer?

> **"How concentrated are the outgoing relationships in this repository's graph, and do a small number of nodes have an unusually large outward structural surface?"**

More specifically: *"When we look at how many outgoing edges each file and symbol has, is the distribution flat and low, or is it skewed by a small number of highly connected nodes?"*

Fan-out measures the **outgoing connectivity** of nodes. A node's fan-out is simply the count of edges that leave it and point to other nodes — how many things it depends on, imports, calls, creates, or otherwise connects to.

High fan-out is the third most heavily weighted metric (18%). It is architecturally significant because:

1. A node with very high fan-out is aware of — and directly depends on — many other parts of the system.
2. If any of those dependencies change (their interface, behavior, or existence), the high-fan-out node must be updated.
3. High fan-out nodes are often the first to accumulate unplanned dependencies over time, acting as "junk drawers" in the codebase.
4. Testing a high-fan-out node requires setting up or mocking many more collaborators.

|-------|------|-------------|

| `maximumFanOut` | `number` | The highest fan-out observed for any single relevant node. |

## What "Fan-out" Means

For a single node $n$, its fan-out is:

$$
\text{FanOut}(n) = |\text{OutgoingEdges}(n)|
$$

This is the count of edges leaving the node, regardless of what relationship kind they represent (import, call, extends, etc.).

### ASCII illustration

```
        ┌── B
        ├── C
A ──────┼── D
        ├── E
        └── F
```

Node `A` has a fan-out of 5. Nodes B, C, D, E, and F each have a fan-out of 0 (no outgoing edges shown here).

## Raw Measurements

The calculator accumulates three values in a single pass:

```ts
let totalFanOut  = 0;
let squaredFanOut = 0;
let maximumFanOut = 0;

for (const nodeId of nodeIds) {
    const fanOut = graph.outgoingEdges.get(nodeId)?.size ?? 0;

    totalFanOut   += fanOut;
    squaredFanOut += fanOut * fanOut;
    maximumFanOut  = Math.max(maximumFanOut, fanOut);
}
```

### Average fan-out

$$
\text{AverageFanOut} = \frac{\sum_{n} \text{FanOut}(n)}{N}
$$

The arithmetic mean. This gives the "typical" outgoing degree across all nodes.

### Root Mean Square fan-out

$$
\text{RMS}_{\text{FanOut}} = \sqrt{\frac{\sum_{n} \text{FanOut}(n)^2}{N}}
$$

The root mean square. Squaring individual values before averaging amplifies the contribution of nodes with high fan-out, making the metric sensitive to connectivity concentration.

### Maximum fan-out

$$
\text{MaxFanOut} = \max_{n} \text{FanOut}(n)
$$

The single highest fan-out observed. Used for reporting and debugging — it identifies the most connected node. Not used in the health score itself, but useful for understanding the tail of the distribution.

---

## Why RMS Instead of Average?

Consider two repositories, each with 5 nodes:

**Repository A:**
```text
FanOut: 1, 1, 1, 1, 1
Average = 1.0
RMS     = 1.0
```

**Repository B:**
```text
FanOut: 0, 0, 0, 0, 5
Average = 1.0
RMS     = sqrt((0+0+0+0+25)/5) = sqrt(5) ≈ 2.24
```

Both repositories have the same average fan-out. But Repository B has a single node with fan-out 5 — a structural hotspot that creates asymmetric dependency on that node.

The RMS captures this concentration because squaring creates a penalty proportional to the square of the excess. A node with fan-out 5 contributes 25 to the squared sum, while five nodes with fan-out 1 contribute only 1 each (total: 5). The RMS is therefore 2.24 for B vs 1.0 for A — a meaningful difference.

Average fan-out is still reported in the result (`averageFanOut`) because it is useful context when interpreting the RMS. If RMS is much larger than Average, that indicates a skewed distribution.

---

## Normalization

### Calibration factor

$$
F_{\text{fanOut}} = 0.5
$$

### Normalized risk

$$
\text{NormalizedRisk} = F_{\text{fanOut}} \times \text{RMS}_{\text{FanOut}}
$$

### Health score

$$
\text{FanOutHealth} = \frac{100}{1 + \text{NormalizedRisk}}
$$

$$
\text{FanOutHealth} = \frac{100}{1 + 0.5 \times \text{RMS}_{\text{FanOut}}}
$$

This is **reciprocal normalization**. The score starts at 100 when RMS is 0 and decreases continuously. Unlike the cycle metric, there is no hard upper cap on risk — extremely high RMS values continue to push the score toward 0 (without ever reaching it).

---

## Score Behavior Table

| RMS FanOut | NormalizedRisk | FanOutHealth |
|-----------|---------------|-------------|
| 0.0 | 0.00 | 100.0 |
| 0.5 | 0.25 | 80.0 |
| 1.0 | 0.50 | 66.7 |
| 2.0 | 1.00 | 50.0 |
| 4.0 | 2.00 | 33.3 |
| 8.0 | 4.00 | 20.0 |
| 19.0 | 9.50 | 9.5 |

An RMS fan-out of 2 corresponds to a health score of exactly 50. That means: the "root-mean-square" outgoing connectivity is 2 edges per node.

## Full Implementation

```ts
const FAN_OUT_FACTOR = 0.5;

export function calculateFanOutHealth(graph: Graph): FanOutHealthResult {
    const nodeIds = [
        ...(graph.nodesByKind.get("file")   ?? new Set<string>()),
        ...(graph.nodesByKind.get("symbol") ?? new Set<string>()),
    ];

    if (nodeIds.length === 0) {
        return { score: 100, averageFanOut: 0, rootMeanSquareFanOut: 0, maximumFanOut: 0 };
    }

    let totalFanOut   = 0;
    let squaredFanOut = 0;
    let maximumFanOut = 0;

    for (const nodeId of nodeIds) {
        const fanOut = graph.outgoingEdges.get(nodeId)?.size ?? 0;

        totalFanOut   += fanOut;
        squaredFanOut += fanOut * fanOut;
        maximumFanOut  = Math.max(maximumFanOut, fanOut);
    }

    const averageFanOut        = totalFanOut / nodeIds.length;
    const rootMeanSquareFanOut = Math.sqrt(squaredFanOut / nodeIds.length);
    const normalizedRisk       = FAN_OUT_FACTOR * rootMeanSquareFanOut;
    const score                = 100 / (1 + normalizedRisk);

    return { score, averageFanOut, rootMeanSquareFanOut, maximumFanOut };
}
```

## Worked Examples

### Example A — Sparse, uniform repository

```text
Nodes: 1000 (all files and symbols)
FanOut distribution: all between 0 and 2

totalFanOut   = 500
squaredFanOut = 500   (most are 0 or 1)
maximumFanOut = 2

averageFanOut        = 500 / 1000 = 0.500
rootMeanSquareFanOut = sqrt(500 / 1000) = sqrt(0.5) ≈ 0.707
normalizedRisk       = 0.5 × 0.707 = 0.354
FanOutHealth         = 100 / 1.354 ≈ 73.9
```

Uniformly moderate fan-out produces a health in the 70s — decent, but not excellent.

### Example B — Concentrated fan-out (hotspot)

```text
Nodes: 1000
999 nodes have fanOut = 0
1 node has fanOut = 43 (the maximum observed)

totalFanOut   = 43
squaredFanOut = 1849 (43²)
maximumFanOut = 43

averageFanOut        = 43 / 1000 = 0.043
rootMeanSquareFanOut = sqrt(1849 / 1000) = sqrt(1.849) ≈ 1.360
normalizedRisk       = 0.5 × 1.360 = 0.680
FanOutHealth         = 100 / 1.680 ≈ 59.5
```

The single node with fan-out 43 dramatically inflates the RMS compared to the arithmetic average (0.043 vs 1.36). The health score of 59.5 is far lower than what the average would suggest. This is exactly the behavior RMS is intended to produce — it amplifies the architectural significance of the high-fan-out hotspot.

### Example C — High uniform fan-out

```text
Nodes: 100
All nodes have fanOut = 5

totalFanOut   = 500
squaredFanOut = 2500
maximumFanOut = 5

averageFanOut        = 5.0
rootMeanSquareFanOut = sqrt(2500 / 100) = sqrt(25) = 5.0
normalizedRisk       = 0.5 × 5 = 2.5
FanOutHealth         = 100 / 3.5 ≈ 28.6
```

When average and RMS are equal, the distribution is uniform. Here, every node has exactly 5 outgoing edges — a significant outward surface for each node. The score of 28.6 is in the "Significant structural concerns" range.

---

## Interpreting the Score in Context

| FanOutHealth | What It Typically Means |
|--------------|------------------------|
| 80 – 100 | Very low RMS fan-out. Most nodes have few or no outgoing edges. |
| 60 – 80  | Moderate RMS fan-out. Some nodes have higher connectivity but no severe hotspots. |
| 40 – 60  | Elevated RMS fan-out. Either many nodes have moderate fan-out, or a few have very high fan-out. |
| 20 – 40  | High RMS fan-out. Structural dependency concentration is a concern. |
| 0 – 20   | Very high RMS fan-out. Architectural "god nodes" likely exist. |

---

## Reading Average vs. RMS Together

| averageFanOut | rootMeanSquareFanOut | Implication |
|--------------|----------------------|-------------|
| Low | Low | Sparse, flat graph. Most nodes are leaves or near-leaves. |
| Low | High | A small number of very high fan-out hotspots exist among many near-zero nodes. |
| High | ≈ Average | Uniformly dense graph. Fan-out is broadly distributed. |
| High | >> Average | Already-high fan-out is further concentrated in a subset of nodes. |

The gap between average and RMS is the diagnostic signal. When RMS >> Average, there are structural outliers worth investigating.

---

## Calibration Parameter

The factor `0.5` means a "50% health" threshold at `RMS = 2`:

$$
\frac{100}{1 + 0.5 \times 2} = \frac{100}{2} = 50
$$

Reducing the factor to `0.25` would move the 50% threshold to `RMS = 4`, making the metric more lenient.

Increasing the factor to `1.0` would move the 50% threshold to `RMS = 1`, making it stricter.
