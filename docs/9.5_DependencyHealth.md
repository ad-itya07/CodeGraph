# 9.5 Dependency Health

## What Question Does This Answer?

> **"How heavily do repository files reach out to external packages and third-party libraries?"**

More specifically: *"On average, how many file-to-dependency graph edges exist per repository file?"*

Dependency Health measures the **density of external dependency relationships** across the repository's files. It is not simply a count of unique packages used — it measures the number of times repository files establish graph relationships with dependency nodes, giving a picture of how broadly external packages are woven into the file structure.

Dependency Health is the fifth most weighted metric (10%). It is given a lower weight than the structural metrics (cycles, coupling, fan-in, fan-out) because:

1. External dependencies are a normal and necessary part of any software project.
2. High dependency usage does not automatically imply poor architecture — it often reflects appropriate reuse.
3. The metric captures a risk dimension (external exposure, version coupling, transitive vulnerability surface) but this risk is typically secondary to internal structural problems.

## TypeScript Interface

```ts
export interface DependencyHealthResult {
    score: number;
    dependencyRelationshipCount: number;
    fileCount: number;
    averageDependenciesPerFile: number;
}
```

| Field | Type | Description |
|-------|------|-------------|
| `score` | `number` | Normalized health score, 0–100. Higher is healthier. |
| `dependencyRelationshipCount` | `number` | Total number of file→dependency edges in the graph. |
| `fileCount` | `number` | Total number of file nodes in the graph. |
| `averageDependenciesPerFile` | `number` | `dependencyRelationshipCount / fileCount`. The primary health input. |

---

## What "Dependency Relationship" Means

In CodeGraph's graph model, external packages are represented as **dependency nodes** (`kind === "dependency"`).

When a repository file imports or uses an external package, CodeGraph creates an edge from the file node to the dependency node.

The dependency relationship count is **not** the number of unique packages. It is the number of such edges in the graph.

### Example

```
File A  ──imports──►  lodash   (dependency node)
File B  ──imports──►  lodash   (same dependency node)
File C  ──imports──►  express  (dependency node)
```

In this example:
- Unique dependency nodes: 2 (lodash, express)
- Dependency relationship count: 3 (three edges)
- File count: 3

$$
\text{AverageDependenciesPerFile} = \frac{3}{3} = 1.0
$$

The metric counts edges, not unique packages, because edges reflect how pervasively external packages are used across the file structure.

---

## How Dependency Relationships Are Counted

```ts
let dependencyRelationshipCount = 0;

for (const fileId of fileIds) {
    const edgeIds = graph.outgoingEdges.get(fileId) ?? new Set<string>();

    for (const edgeId of edgeIds) {
        const edge = graph.edges.get(edgeId);
        if (!edge) continue;

        const targetNode = graph.nodes.get(edge.targetId);

        if (targetNode?.kind === "dependency") {
            dependencyRelationshipCount++;
        }
    }
}
```

The algorithm iterates over every file node's outgoing edges and increments the count when the edge's target is a dependency node. Only file-to-dependency edges are counted; edges between files, or file-to-symbol edges, are excluded.

---

## Raw Measurement

$$
\text{AverageDependenciesPerFile} = \frac{\text{DependencyRelationshipCount}}{\text{TotalFiles}}
$$

If `TotalFiles = 0`, the function returns early with:

```ts
{ score: 100, dependencyRelationshipCount: 0, fileCount: 0, averageDependenciesPerFile: 0 }
```

### Scale invariance

This average makes the metric independent of repository size:

```text
Repository A:  100 files,  150 dep relationships → avg = 1.5
Repository B: 1000 files, 1500 dep relationships → avg = 1.5
```

Both repositories have the same external dependency density, even though their absolute counts differ by 10x. The metric treats them equally.

---

## Normalization

### Calibration factor

$$
F_{\text{dependency}} = 0.5
$$

### Normalized risk

$$
\text{NormalizedRisk} = 0.5 \times \text{AverageDependenciesPerFile}
$$

### Health score

$$
\text{DependencyHealth} = \frac{100}{1 + 0.5 \times \text{AverageDependenciesPerFile}}
$$

This is **reciprocal normalization**, identical in form to the coupling, fan-out, and fan-in formulas.

---

## Score Behavior Table

| AvgDepsPerFile | NormalizedRisk | DependencyHealth |
|---------------|---------------|-----------------|
| 0.0 | 0.00 | 100.0 |
| 0.5 | 0.25 | 80.0 |
| 1.0 | 0.50 | 66.7 |
| 2.0 | 1.00 | 50.0 |
| 4.0 | 2.00 | 33.3 |
| 8.0 | 4.00 | 20.0 |

A score of 66.7 corresponds to exactly 1 external dependency relationship per file on average.

## Full Implementation

```ts
const DEPENDENCY_FACTOR = 0.5;

export function calculateDependencyHealth(graph: Graph): DependencyHealthResult {
    const fileIds = graph.nodesByKind.get("file") ?? new Set<string>();

    if (fileIds.size === 0) {
        return { score: 100, dependencyRelationshipCount: 0, fileCount: 0, averageDependenciesPerFile: 0 };
    }

    let dependencyRelationshipCount = 0;

    for (const fileId of fileIds) {
        const edgeIds = graph.outgoingEdges.get(fileId) ?? new Set<string>();

        for (const edgeId of edgeIds) {
            const edge = graph.edges.get(edgeId);
            if (!edge) continue;

            const targetNode = graph.nodes.get(edge.targetId);

            if (targetNode?.kind === "dependency") {
                dependencyRelationshipCount++;
            }
        }
    }

    const averageDependenciesPerFile = dependencyRelationshipCount / fileIds.size;
    const normalizedRisk             = DEPENDENCY_FACTOR * averageDependenciesPerFile;
    const score                      = 100 / (1 + normalizedRisk);

    return { score, dependencyRelationshipCount, fileCount: fileIds.size, averageDependenciesPerFile };
}
```

## Worked Examples

### Example A — Minimal dependencies

```text
Files: 200
Dependency relationships: 50

averageDependenciesPerFile = 50 / 200 = 0.25
normalizedRisk             = 0.5 × 0.25 = 0.125
DependencyHealth           = 100 / 1.125 ≈ 88.9
```

Very few external dependencies used per file. High health score.

### Example B — Realistic project (Fuel-TS-scale)

```text
Files: 1170
Dependency relationships: 1248

averageDependenciesPerFile = 1248 / 1170 ≈ 1.067
normalizedRisk             = 0.5 × 1.067 ≈ 0.534
DependencyHealth           = 100 / 1.534 ≈ 65.2
```

Roughly one external dependency relationship per file. Score in the 60s — in the "Noticeable structural complexity" zone, primarily because external dependencies have meaningful accumulation across the file base.

### Example C — Heavy dependency usage

```text
Files: 300
Dependency relationships: 1200

averageDependenciesPerFile = 1200 / 300 = 4.0
normalizedRisk             = 0.5 × 4.0 = 2.0
DependencyHealth           = 100 / 3.0 ≈ 33.3
```

Four external dependency relationships per file on average is quite high. Score of 33.3 signals that external exposure is a dominant characteristic of this codebase.

---

## Interpreting the Score in Context

| DependencyHealth | What It Typically Means |
|------------------|------------------------|
| 85 – 100 | Very low external dependency density. The codebase is largely self-contained. |
| 65 – 85  | Moderate dependency usage. About 0–1.5 external relationships per file. Normal for most projects. |
| 45 – 65  | Above-average dependency density. Consider whether all usages are necessary. |
| 25 – 45  | High dependency density. Multiple external packages per file on average. |
| 0 – 25   | Very high density. External packages are pervasively used throughout the file structure. |

---

## Important Nuances

### This metric does not penalize dependency count directly

A repository that uses many different packages but confines their usage to a small number of adapter/wrapper files may have a low `averageDependenciesPerFile` and therefore a high health score. This is structurally good — dependencies are centralized rather than scattered.

A repository that uses few packages but imports them in every single file will have a higher average and a lower score, reflecting the structural dispersion of external coupling.

### The metric captures structural coupling, not quality

A high dependency score does not mean the dependencies are bad choices. It reflects a structural fact about how broadly external packages are coupled to the repository's file structure.

### File count is the denominator, not node count

Unlike coupling, fan-in, and fan-out (which use all relevant nodes), this metric uses only file nodes as the denominator. Symbol nodes do not import dependencies — only files do. Using all nodes would artificially inflate the denominator and mask the true per-file density.

---

## Calibration Parameter

The `0.5` factor has the same interpretation as other reciprocal-normalized metrics:

$$
\text{AvgDepsPerFile} = 2 \Rightarrow \text{Health} = 50
$$

Reducing to `0.25` would put the 50% threshold at 4 deps/file. Increasing to `1.0` would put the 50% threshold at 1 dep/file.
